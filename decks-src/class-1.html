It holds your files, plus the full history of every change: who changed what, and when.
People shorten it to repo. One project, one repo.

Who can see it?

Public or private.

Public
Anyone on the internet can see it. Only you, and people you add, can change it. Good for portfolio work.
Private
Only you, and people you invite, can see it. Good for unfinished work or anything personal.
Never put passwords or API keys in any repo, public or private.
Public: anyone can see, only collaborators can change. Private: only you and invited people can see.

.md = Markdown
README.md is the front page of a repository, shown under the file list. It is written in Markdown: simple symbols that GitHub turns into formatting.
Cheat sheet

Six Markdown symbols.

You typeYou get
# TitleA big heading (## for smaller)
**bold**bold text
*italic*italic text
- itemA bullet list
[text](https://link)A clickable link
`code`code in a box
Six symbols cover almost every README: headings, bold, italic, lists, links and code.
Edit on the website

Pencil, edit, Commit changes.

1
Open README.md, click the pencil icon
2
Edit, then check the Preview tab
3
Click Commit changes
Type a short message saying what you changed.
Remember this word
commit
A saved version with a message. GitHub runs Git for you when you press that button. Next class, you run Git yourself.
Every edit on GitHub ends with Commit changes. That is a commit, a saved version with a message. Next class, students make commits themselves with Git.
Removing data

Delete one file.

1
Click the file to open it
2
Open the ⋯ menu at the top right of the file
3
Choose Delete file
4
Commit changes
Yes, deleting is a commit too.
The old version is still in history.
Deleting removes it from the latest version, not from past commits. That is why secrets must never be committed.
Open the file, use the three-dot menu, Delete file, Commit changes. The file stays in the history of earlier commits.
