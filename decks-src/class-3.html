03 Everyone hits these

Three things that look scary, and are not.

1
A strange editor opened
You forgot -m. If it is Vim (full screen, no menus), quit with:
Esc:q!Enter
In Notepad: type a message on line 1, save, close.
2
A warning about LF and CRLF

Normal on Windows; it ends lines differently. Ignore it, your command worked.
3
“Please tell me who you are”

04 All you need

Four commands to branch.

CommandWhat it does
git branch feature-branchCreates a branch. You do not move onto it.
git checkout feature-branchMoves you onto that branch. git switch also works.
git branchLists branches. * marks the one you are on.
git merge feature-branchBrings that branch's commits into the branch you are on.
TIME: 52 to 54 min. SAY: Four commands. branch creates, but does not move you. checkout moves you. branch on its own lists them, and the star is where you are. merge brings another branch's work into the one you are standing on. TIP: The most common mistake is merging while on the wrong branch. Check git branch first.

04 Not every merge is a fast-forward

Three ways a merge can go.

Fast-forward
Just slide forward
Master did not move. Git moves the label. No new commit.
Three-way merge
Both moved
Different parts changed. Git makes a new merge commit joining both.
Conflict
Same lines changed
Git will not guess. It pauses and asks you to choose.
TIME: 84 to 88 min. SAY: What we did is the simplest case, a fast-forward. When both branches have new commits in different places, Git joins them with a new merge commit, a three-way merge. When both changed the very same lines, Git stops and asks you. That is a conflict.

Stage and commit

TIME: 88 to 91 min. Concept only today; practice comes later. SAY: A conflict means two people changed the same lines differently, and Git refuses to guess. Open the file. The top part is your version, the bottom part is the incoming one. Keep what is right, delete the rest and the three marker lines, save, add, commit. 05 Experiment 3

Stash is a drawer for unfinished work.

switching with unfinished changes

error: Your local changes to the following files
would be overwritten by checkout:
notes.txt
Please commit your changes or stash them

TIME: 96 to 99 min. ASK: You are half-way through, not ready to commit, and must switch branches now. What do you do? Take answers. SAY: If you try to switch, Git may refuse, because your unfinished change would be overwritten. That is this error. Committing half-finished work pollutes history. Stash is a drawer: put the work away, switch, come back, take it out.

TIME: 99 to 110 min. Six presses. DO step 1: make a branch to switch to: git branch other-branch. Add an unfinished line to notes.txt with echo and TWO greater-than signs (two adds to the end; one would overwrite the file). git status --short shows M: modified. The drawer slides open. DO step 2: git stash. The change goes into the drawer. The desk is clean. DO step 3: git stash list. One entry, stash@{0}. The drawer closes. DO step 4: git checkout other-branch. Imagine the urgent fix here. DO step 5: git checkout master. Back where you were. DO step 6: git stash pop. The drawer opens, the unfinished line comes back, and the entry is removed. ASK: What happened to your changes when you ran git stash? Answer: saved aside, nothing lost, working folder back to the last commit. TIP: Run cat notes.txt after pop to prove the line is back.
05 The stash family

Four stash commands.

CommandWhat it does
git stashPut unfinished changes in the drawer. Desk is clean.
git stash listSee everything in the drawer.
git stash popTake the newest one back out and remove it from the drawer.
git stash applyBring it back but keep a copy in the drawer.
TIME: 110 to 112 min. SAY: Pop takes it out and throws away the drawer copy. Apply brings it back and keeps a copy. You can stash more than once; list shows them all, and the newest is stash@{0}.
